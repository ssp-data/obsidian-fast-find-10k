# Fast Find 10K Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Obsidian plugin ("Fast Find 10K") whose Rust/WASM engine, running in a Web Worker, finds a known note in one try in a 10k-note vault, with a Telescope-style modal, near-duplicate detection, note creation and optional Smart Connections semantics.

**Architecture:** A pure Rust crate (`ff10k-core`) owns parsing, indexing, matching and ranking and is tested natively with a synthetic fixture vault and golden queries. A thin `wasm-bindgen` crate exposes it to a TypeScript worker; the TypeScript plugin shell handles Obsidian I/O (vault events, cache in IndexedDB, metadata, Smart Connections bridge) and the modal UI. A CLI crate drives the same core against the full local test vault for tuning.

**Tech Stack:** Rust 1.99 (stable), `neo_frizbee` 0.13 (SIMD fuzzy), `serde`/`serde_json`, `unicode-normalization`, `wasm-bindgen`, `criterion`; TypeScript, esbuild, Obsidian API 1.5+, IndexedDB; Node 26.

**Spec:** `docs/superpowers/specs/2026-10-26-fast-find-10k-design.md`

## Global Constraints

- Plugin id `fast-find`, display name `Fast Find 10K`. Never the word "Obsidian" in the name.
- Markdown only. Never enumerate or index images, PDFs, canvas, or dot-folders (`.obsidian/`, `.trash/`, `.smart-env/`).
- Obsidian "Excluded files" (`app.metadataCache.isUserIgnored(path)`) → never indexed, never shown.
- All engine work in the worker; the UI thread never parses or scores. No input debounce.
- Release artifacts: exactly `main.js`, `manifest.json`, `styles.css`; wasm and worker embedded in `main.js`, `main.js` < 3 MB.
- Budgets (10k notes / 30 MB): warm start → searchable < 1 s; query engine p95 < 10 ms; keystroke → paint < 30 ms; semantic query < 100 ms; worker memory < 150 MB.
- Field weights (defaults): title 100, alias 90, h1 60, h2 50, h3 40, tag 30, link 20, path 15, body 10. Downranked folders multiplier 0.3.
- Frecency: `Σ exp(−0.0693 × days)` over 30 days, cap `10 + sqrt(x − 10)` above 10, max 128 timestamps per path. Combo: ≥ 3 opens of the same note for the same normalized query → sticky boost.
- Smart Connections target version 4.7.2; all access through one bridge module; never throw when absent.
- Tests and fixtures never read the owner's live vault. Repo fixtures are synthetic. Local tuning uses `<vault>`.
- Commit locally after each task. Do not push.

## Review Focus

1. Malformed or absent frontmatter (unterminated `---`, `aliases:` as scalar vs list, tags with `#` prefix) → the note is still indexed and its body is not swallowed. Pinned in Task 4.
2. A single huge note (≥ 2 MB) → indexing, excerpt and preview stay within budget; positions capped, no quadratic behaviour. Pinned in Task 6.
3. Queries that are only syntax (`#`, `path:`, `""`, `-`, whitespace) → no panic, empty-query behaviour or empty result, never a crash. Pinned in Task 5.
4. Two notes with the same basename in different folders → both shown with distinct paths, link insertion resolves to the selected file, dedup flags "same title, different folder". Pinned in Task 10 and Task 19.
5. Smart Connections vectors with mismatched dims or count → feature disabled with one console warning, lexical search unaffected. Pinned in Task 11 and Task 20.
